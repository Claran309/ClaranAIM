# Change Note: GraphRAG 抽取规则收敛

## 1. What Changed

本次修改把知识图谱实体/关系抽取进一步收敛为“AI 主抽取、规则只兜底”的模式：

- LLM GraphRAG prompt 改为分析型任务：先判断章节主题，再抽真正关键的实体和关系。
- LLM 每个章节最多抽 6 个实体和 6 条关系，明确要求“宁缺毋滥”。
- 规则兜底不再抓普通英文大写词、教学样例和普通中文概念。
- 规则兜底只保留强结构技术实体，例如 `agent-manager-service`、`agent_dispatch_records`、`event_outbox`、`claran.im.events` 这类服务、表、事件主题或 API。
- 规则兜底抽出的孤立节点如果没有参与关系，不再进入图谱。
- 新增测试覆盖普通样例词不会进入图谱，例如 `Teacher`、`Student`、`Customer`、`Linux`。

这是 GraphRAG 抽取质量修复，不涉及数据库 schema 变化。

## 2. Why This Change Was Needed

之前的规则抽取承担了太多“语义判断”工作。规则擅长识别固定形态，比如服务名、表名、Topic，但不擅长判断一篇文章真正重要的概念。结果就是它容易把普通例子、标题词、英文大写词、短中文词也当成实体。

更合理的边界是：

```text
LLM：判断哪些实体和关系重要
代码：约束 JSON 格式、过滤明显噪声、保存事实
规则：只在没有 LLM 时做最低限度强结构兜底
```

这个取舍会让图谱更少，但更可信。知识图谱不是关键词云，宁愿少几个节点，也不应该堆满不重要的词。

## 3. Files Changed

- `internal/rag-service/service/service.go`: 重写 LLM 图谱抽取提示词，收紧规则兜底实体识别，新增规则抽取孤立节点过滤。
- `internal/rag-service/service/service_test.go`: 更新默认规则兜底测试输入，新增普通教学样例不入图谱的回归测试。

## 4. Core Flow After The Change

配置了 LLM 图谱抽取器时：

```text
parent chunk / 章节内容
  -> LLM 分析章节主题
  -> LLM 输出核心 entities / relationships JSON
  -> 代码过滤明显噪声和无证据关系
  -> 写入 rag_entities / rag_relations
```

没有 LLM 图谱抽取器时：

```text
parent chunk / 章节内容
  -> 规则只识别强结构名称
  -> 只保留能形成明确关系的实体
  -> 写入少量兜底图谱
```

## 5. Key Code Concepts

**AI 主抽取**

GraphRAG 的核心不是“抓词”，而是“判断文章里的关键对象和对象之间的关系”。这类判断更适合 LLM，所以 prompt 现在明确要求模型先理解主题，再抽实体关系。

**强结构兜底**

规则兜底只识别非常稳定的技术形态，例如 `-service`、`_records`、`_outbox`、`.events`。这些形态不需要太多语义判断，也不容易误伤。

**孤立节点过滤**

规则抽取出来的节点如果没有任何关系，通常只是关键词，不适合作为知识图谱节点。现在这类节点会被过滤掉。

## 6. Important Implementation Details

- LLM prompt 明确禁止抽取普通数字、序号、页码、字段名、状态词、文件名、图片名、临时变量、教学样例、会话摘要和泛词。
- LLM prompt 明确禁止强行输出 `RELATED_TO`，只有存在明确动作或语义时才允许建立关系。
- 规则兜底移除了普通 CamelCase / 大写词扫描，所以 `Teacher`、`Linux` 这类词不会再被当作实体。
- `event_outbox` 被纳入强结构数据实体模式，避免 Outbox 表这类真实技术实体被误删。

## 7. How To Verify

已执行：

```bash
go test ./internal/rag-service/service
```

建议继续手动验证：

```text
1. 重新上传或重建一个普通教学文档，确认图谱不再出现 Teacher、Student、Customer、Linux 等样例节点。
2. 上传项目技术文档，确认 agent-manager-service、agent_dispatch_records、event_outbox、claran.im.events 这类强结构实体仍可生成。
3. 配置可用 LLM Router 后重新入库文档，确认图谱节点更接近文章核心概念，而不是关键词列表。
```
