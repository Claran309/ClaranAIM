# Change Note: GraphRAG 概念小图兜底

## 1. What Changed

本次调整 GraphRAG 抽取合格标准，避免规则过严导致正常文档没有知识图谱：

- 强动作关系仍然优先，例如 `CALLS`、`WRITES`、`DEPENDS_ON`、`CONSUMES`。
- 如果文档没有动作型关系，但 LLM 给出高置信、证据清楚、描述具体的 `RELATED_TO` 语义关联，也允许生成小型概念图。
- 弱 `RELATED_TO` 仍然拒绝，例如“同段出现、一起出现、提到了、相关”这类泛泛关系。
- 增加测试区分“弱相关图谱应拒绝”和“高质量语义关联图谱应保留”。

## 2. Why This Change Was Needed

上一轮质量门槛强调“必须有强关系”，这对项目架构文档很合适，但对简历、课程资料、业务说明、政策说明这类文档会过严。

这些文档不一定存在“调用、写入、发布、消费”这样的动作关系，但仍可能存在有价值的语义结构：

```text
融媒体中心面试简历
  RELATED_TO 新闻采编能力
  evidence: 简历需要体现新闻采编能力、内容策划能力和新媒体运营能力
```

这种关系不是服务调用图，但它能帮助用户理解文档核心概念，因此应该允许形成小图。

## 3. Files Changed

- `internal/rag-service/service/service.go`: `graphExtractResultQualified` 增加高质量 `RELATED_TO` 语义关系判断，新增 `isHighQualitySemanticRelation`。
- `internal/rag-service/service/service_test.go`: 增加高质量概念小图允许测试，并保留弱相关图拒绝测试。

## 4. Core Flow After The Change

```text
抽取实体关系
  -> 过滤噪声实体和低质量关系
  -> 如果存在强动作关系：合格
  -> 否则检查 RELATED_TO 是否高置信、证据具体、不是同段出现
  -> 合格则生成小型概念图
  -> 不合格则整段不入图谱
```

## 5. Key Code Concepts

**强关系图**

适合技术架构、服务链路、数据流文档。关系表达明确动作，例如“服务写入表”“服务消费事件”。

**概念小图**

适合业务说明、简历、课程资料、知识文章。关系不是调用链，但能表达“核心主题包含/体现/覆盖某个关键维度”。

**弱相关过滤**

`RELATED_TO` 不是不能用，而是不能滥用。只说“同段出现”或“提到了”的关系不进入图谱。

## 6. Important Implementation Details

- `RELATED_TO` 需要置信度至少 `0.9`。
- 描述或证据不能包含“同段出现、一起出现、提到了”等弱相关短语。
- 描述或证据需要包含“包含、组成、属于、用于说明、定义、体现、支撑、覆盖、核心内容、关键维度”等语义信号，或者文本足够具体。
- 规则兜底仍然严格，不会因为这个调整重新抓普通示例词。

## 7. How To Verify

已执行：

```bash
go test ./internal/rag-service/service
```

建议手动验证：

```text
1. 上传一份非技术文档，确认如果模型抽出高质量概念关系，图谱不再为空。
2. 上传噪声较多的课程示例，确认“同段出现”式弱关系仍不会生成图谱。
3. 上传项目架构文档，确认强动作关系仍优先展示。
```
