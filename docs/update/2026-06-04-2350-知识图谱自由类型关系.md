# Change Note: 知识图谱自由类型关系

## 1. What Changed

本次把知识图谱从“固定实体类型 + 固定关系类型”改成“LLM 自由类型 + LLM 自由关系”的抽取和展示方式。

- `internal/rag-service/service/service.go`: 调整 GraphRAG 抽取 prompt、实体类型清理、关系清理、文档根节点类型和旧图谱诊断。
- `pkg/knowledgeclient/rag_backed.go`: 保留 RAG 返回的原始实体类型和关系，不再压成 `Concept` 或 `RELATED_TO`。
- `dist/js/app.js` / `dist/js/api.js`: 前端知识图谱不再发送关系筛选参数，类型筛选改为从当前图谱动态生成，并在详情中显示 LLM 类型/LLM 关系。
- `internal/rag-service/service/service_test.go` / `pkg/knowledgeclient/view_test.go`: 增加自由类型、自由关系和泛化关系过滤的回归测试。

这是一次知识图谱抽取质量和展示保真的 bug fix，同时也是 GraphRAG indexing 行为调整。

## 2. Why This Change Was Needed

之前的图谱链路有两层压扁：

1. RAG 后处理会把 LLM 输出的未知实体类型推断或归一为固定类型，最坏会落到 `Concept`。
2. `knowledgeclient` 会把前端不认识的类型显示成 `Concept`，把未知关系显示成 `RELATED_TO`。

结果就是即使 LLM 抽出了“岗位”“能力”“穿着”“需要体现”这类更贴近文档语义的标签，前端仍可能看到“概念”和“相关”。这会让图谱看起来像一团没有信息量的线。

新设计的取舍是：系统不再假装自己比 LLM 更懂文档类型，只负责过滤明显泛化和噪声标签。比如“相关”“关联”“提到”会被丢弃，但“面向”“需要体现”“穿着”会保留。

## 3. Files Changed

- `internal/rag-service/service/service.go`: GraphRAG prompt 改为要求 LLM 输出短而具体的类型/关系；`normalizeEntityTypeWithContext` 和 `normalizeRelationType` 只清理噪声，不压扁未知标签；文档标题节点类型改为 `文档`。
- `pkg/knowledgeclient/rag_backed.go`: `displayEntityType` 直接保留原始类型；`normalizeRelation` 直接保留原始关系；泛化关系返回空并被过滤。
- `dist/js/api.js`: 知识图谱查询不再传 `relations` 参数。
- `dist/js/app.js`: 删除固定关系筛选；实体类型筛选改为基于当前返回图谱动态生成；节点详情显示“LLM 类型”，边详情显示“LLM 关系”。
- `internal/rag-service/service/service_test.go`: 覆盖“岗位/能力/文档”和“需要体现/面向/穿着”不会被压扁。
- `pkg/knowledgeclient/view_test.go`: 覆盖 knowledgeclient 到前端前仍保留自由类型和自由关系。

## 4. Core Flow After The Change

```text
文档入库
  -> RAG 分块
  -> GraphRAG LLM 抽取实体和关系
  -> 过滤泛化类型/泛化关系/噪声节点
  -> 保存文档根节点「文档」
  -> 保存 LLM 原始实体类型和关系
  -> knowledge-service 查询图谱
  -> knowledgeclient 保留原始类型/关系
  -> 前端动态渲染类型筛选、节点详情和边详情
```

如果某篇文档只有根节点或只有 `CONTAINS` / `包含` 骨架，前端会提示这可能是 LLM 抽取为空、旧图谱未重建或过滤后没有实体间关系，并提供重建入口。

## 5. Key Code Concepts

- **自由类型**：实体类型不再必须是 `Service`、`DatabaseTable` 等固定值。LLM 可以输出“岗位”“能力”“课程主题”“工具”等贴近文档的标签。
- **自由关系**：关系类型不再必须是 `CALLS`、`WRITES` 等固定值。LLM 可以输出“穿着”“需要体现”“面向”等短关系词。
- **泛化标签过滤**：系统会过滤“实体”“节点”“对象”“相关”“关联”“提到”等没有结构信息的标签，防止图谱退化成噪声。
- **文档根节点**：每篇文档仍保留一个固定根节点，类型为 `文档`，通过 `CONTAINS` 连接文档中的核心实体，保证按文档查看时至少有骨架。
- **展示保真**：knowledgeclient 和前端不再擅自把未知标签改成 `Concept` / `RELATED_TO`，避免用户看到的图谱和 LLM 实际抽取结果不一致。
