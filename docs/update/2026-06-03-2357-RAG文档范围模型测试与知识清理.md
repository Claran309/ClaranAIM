# 2026-06-03 RAG 文档范围、模型测试与知识清理

## 本次目标

修复知识工作台、RAG 检索、模型配置、管理台入口和 Agent 自回复相关问题，并按要求清空当前已上传的知识库与知识图谱数据。

## 主要修改

### 1. RAG 文档范围检索

- 前端 RAG 搜索页新增“文档范围”下拉框。
- 从知识工作台或左侧知识侧边栏点击某篇文档时，现在传递真实 `document_id`，不再把文档标题拼进 query。
- `document` 模式会强制检索知识库，即使问题很短也不会被 Adaptive Router 判定为直接回答。
- 检索结果页会展示当前范围、模式、路线、CRAG / Self-RAG 状态、来源文档和 chunk 信息。

### 2. 文档与图谱删除

- 前端知识文档列表新增：
  - “删图谱”：只删除某篇文档贡献的 GraphRAG 关系，保留文档和 RAG 分块。
  - “删除”：删除文档、分块和该文档贡献的图谱。
- 接入后端：
  - `DELETE /rag/documents/:id`
  - `DELETE /rag/documents/:id/graph`

### 3. 大文件上传

- API Gateway 请求体上限从 `96MB` 提升到 `160MB`。
- RAG 单文件上传上限从 `80MB` 提升到 `120MB`。
- 上传仍然是“请求接收后异步解析入库”：用户切换页面不会影响后台解析，前端上传浮窗会继续展示任务状态。

### 4. 模型配置与连通测试

- 系统设置里的 LLM 预设增加 RAG 相关用途：
  - Agent 大模型
  - RAG 回答模型
  - RAG 路由小模型
  - 向量模型
  - OCR 模型
  - Rerank 模型
  - 翻译模型
  - 通用模型
- 前端新增“项目内置模型连通测试”按钮组。
- `settings-service` 的内置模型测试现在会按用途优先读取对应环境变量：
  - `RAG_EMBEDDING_*`
  - `DOCUMENT_OCR_*`
  - `RAG_RERANK_*`
  - `RAG_ROUTER_*`
  - 兜底使用 `LLM_DEFAULT_*`

### 5. 管理台入口

- 管理台前端入口现在常驻显示。
- 非管理员用户看到灰态入口和权限提示，不再像“功能没做”。
- 仍然只有 `admin` 角色可以真正进入治理台。

### 6. Agent 防自回复

- `agent-manager-service` 事件分发器新增防回声判断。
- 即使 `message.created` 事件缺少 `client_msg_id`，只要解析到发送者就是当前 Agent 系统用户，也会跳过，不再触发 Agent 回复自己。
- 补充回归测试覆盖该场景。

### 7. 前端布局与体验

- 知识工作台改为居中展示。
- 知识图谱画布扩大，占据页面主要区域。
- RAG 文档范围行、模型测试面板和灰态按钮增加更清晰的样式。
- 左侧知识侧边栏显示 chunk 数量，并使用真实文档范围检索。

## 已清理的数据

- `knowledge_graph_review_candidates`
- `rag_relations`
- `rag_entities`
- `rag_communities`
- `rag_chunks`

清理后上述表均为 `0` 行。

说明：Milvus 中可能仍有旧 orphan vectors，但当前 RAG 搜索会先从 MySQL 读取可见 chunk，再用 MySQL chunk 做回源校验；由于 MySQL 知识事实已清空，旧向量不会出现在用户检索结果里。后续可以给 rag-service 增加显式 Milvus collection 清理接口。
