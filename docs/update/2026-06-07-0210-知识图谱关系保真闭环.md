# Change Note: 知识图谱关系保真闭环

## 1. What Changed

这次修复的是知识图谱关系从后端到前端的“保真展示”问题。核心变化是：LLM 或规则抽取出的具体关系不再被前端请求遗漏、视图去重吞掉，规则兜底也不再凭相邻实体硬造不可靠关系。

这是一组 bug fix + 前端交互增强 + 测试补强。主要涉及：
- `internal/rag-service/service/service.go`: 收紧规则兜底关系生成，并支持“包括/包含”这类列表关系展开。
- `pkg/knowledgeclient/rag_backed.go`: 调整边去重 key，保留不同文档或不同证据的同类关系边。
- `dist/js/api.js` 和 `dist/js/app.js`: 透传 `relations` 参数，新增关系过滤 chip，并让多条同实体对边用曲线偏移显示。
- `pkg/knowledgeclient/view_test.go`、`internal/rag-service/service/service_test.go`: 增加关系保真的回归测试。

## 2. Why This Change Was Needed

原来的问题不是数据库只能存一种关系，而是链路里有几个地方会让关系看起来“被压成一种”：

- 前端没有把 `relations` 查询参数传给 `/knowledge/*`，所以后端已有的关系过滤能力无法使用。
- `knowledgeclient` 视图层按 `relation + source > target` 去重，同一实体对同一关系如果来自不同文档或不同证据，只会保留权重最高的一条。
- 规则兜底图谱会把相邻实体强行连成“调用或支撑/读写/组成/关联”等推断关系。这种关系没有原句证据，容易在前端表现成不合常理的单一关系。
- 多条同源同目标边在图上重叠，用户即使拿到了多条边，也会误以为只有一条。

新的设计选择是“保真优先”：只清理明显空值、泛化关系和噪声关系，不把自由中文关系模板化；同一实体对允许多条有证据的关系并存。

## 3. Files Changed

- `internal/rag-service/service/service.go`: 删除 fallback 主流程中的相邻实体硬连边；新增列表关系展开，让“认证流程包括登录接口、Token签发、签名算法”能生成多条有原句证据的“包含”关系。
- `pkg/knowledgeclient/rag_backed.go`: `edgeKey` 加入 `document_id` 和 evidence，避免跨文档或多证据关系在视图层被吞。
- `dist/js/api.js`: `knowledgeAPI.graph/node/edge/neighborhood` 透传 `relations` 参数。
- `dist/js/app.js`: 增加关系过滤 chip、把关系过滤写入当前查询参数，并给同一实体对的多条边添加稳定曲线偏移。
- `dist/css/style.css`: SVG fallback 的关系边改成 path 后增加 `fill: none`，避免曲线路径被填充。
- `pkg/knowledgeclient/view_test.go`: 增加同关系跨文档/多证据保留、自由中文关系过滤测试。
- `internal/rag-service/service/service_test.go`: 增加自由中文关系保留、fallback 不硬造相邻实体关系等测试。

## 4. Core Flow After The Change

```text
文档入库 / 图谱重建
  -> rag-service GraphRAG 抽取实体和关系
  -> 只保存有明确证据的实体间关系
  -> fallback 只从原句触发词生成关系，不凭相邻顺序猜关系
  -> knowledge-service 读取 rag-service 子图
  -> knowledgeclient 保留不同文档/证据的同类边
  -> api-gateway 暴露 /knowledge/*?relations=
  -> frontend 生成关系 chip 并透传 relations
  -> G6/SVG 用曲线偏移展示多条同实体对边
```

## 5. Key Code Concepts

**关系保真**

关系保真指的是：模型抽取出的 `relation` 字段在服务边界和前端视图里尽量保持原始语义。例如“面向”“生成”“约束”不应该被折叠成“相关”，也不应该因为不是枚举值而丢失。

**视图层去重**

`knowledgeclient` 不是事实源，它只是把 GraphRAG 原始子图整理成前端画布数据。这里的去重只能去掉完全重复的边，不能把不同文档或不同证据支持的关系合并掉。本次把 `document_id` 和 evidence 纳入 key，就是为了避免视图层误删事实。

**规则兜底**

规则兜底用于 LLM 未配置时给用户最低限度的图谱骨架。它不应该假装理解所有实体关系。现在它只根据句子里的触发词生成关系，例如“包括”“使用”“生成”“依赖”，而不是把相邻实体自动连起来。

**前端关系过滤**

后端早已支持 `relations` 查询参数。前端现在从 `stats.relations` 和当前边集合生成 chip，用户点击后会刷新图谱，并把选中的关系传到接口。

## 6. Important Implementation Details

- 没有改数据库 schema，也没有改 `idl/rag.thrift` 或 `idl/knowledge.thrift`，所以不需要重新生成 Kitex 代码。
- 同一实体对的多条边不会再因为 source/target/relation 相同被吞掉；只有 `relation + source + target + document_id + evidence` 都相同才会被视为重复。
- fallback 删除了“连续主题关系”这类无证据边，但保留了 `CONTAINS` 文档骨架和原句触发词关系。
- G6 和 SVG fallback 都会给平行边添加偏移。这个偏移只是展示属性，不改变边 ID、关系类型或详情查询。
- 旧图谱中已经被错误抽取的关系不会自动变好，需要在前端点击“重建当前图谱”或“重建全部图谱”后重新抽取。
