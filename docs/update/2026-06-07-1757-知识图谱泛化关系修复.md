# Change Note: 知识图谱泛化关系修复

## 1. What Changed

这次修复的是知识图谱里“泛化关系”和“具体关系”混在一起导致的展示与抽取问题。

- 前端不再在 RAG 录入/上传页提供“精细/泛化”关系模式选择。
- GraphRAG 入库统一使用平衡策略：优先保留具体、自由、贴近原文的关系，弱关联只作为可过滤的泛化关系存在。
- 知识图谱画布里的“泛化关系/弱关联”开关只影响前端可视化，不再影响文档入库。
- 展示层不再自动补 `RELATED_TO` 弱关系，避免人工补边盖过真实关系。
- 关系线在 G6 图谱里始终带关系标签，边很多时只缩短标签，不整批隐藏。

这是一次 bug fix，同时包含前端展示行为、GraphRAG 抽取策略和回归测试更新。

## 2. Why This Change Was Needed

原来的设计把两个问题混在了一起：文档入库时选择“泛化/精细”，前端又有“是否显示泛化关系”的开关。这样用户会以为开关能控制显示，但实际数据已经在入库时被决定了。

另外，后端有两类补边逻辑会生成 `RELATED_TO`：

- 文档内某些实体没有具体关系时，入库阶段补弱关联。
- 查询展示时发现孤立实体，又补一层弱关联。

这会让图谱看起来“关系很多”，但很多关系不是来自原文，而是系统为了连通画布推出来的。现在改成保真优先：有证据的具体关系留下，没有证据的弱连接不再伪装成事实。

## 3. Files Changed

- `internal/rag-service/service/service.go`: 统一 GraphRAG 关系模式为平衡策略，取消展示层和入库阶段的弱关联自动补边，并让关系去重保留不同文档/证据的同类边。
- `internal/rag-service/service/graph_relationship_extraction_test.go`: 增加回归测试，证明展示层不会再合成泛化边，并证明自由中文关系可以通过过滤。
- `internal/knowledge-service/service/graph_view.go`: 收窄泛化关系识别，避免把包含泛化词片段的自由关系误转成 `RELATED_TO`。
- `internal/knowledge-service/service/graph_view_test.go`: 增加关系保真测试，确认同关系不同证据/文档不会被视图层吞掉。
- `dist/js/app.js`: 删除 RAG 录入页关系模式选择，修复泛化关系开关过滤，关闭泛化时移除因此孤立的节点，并让关系线标签持续可见。
- `dist/js/api.js`: 上传文件时不再发送 `graph_relation_mode`。

## 4. Core Flow After The Change

```text
文档录入或上传
  -> api-gateway 保留旧 graph_relation_mode 字段兼容
  -> rag-service 统一归一为 balanced
  -> GraphRAG LLM/规则抽取具体关系和少量有证据弱关系
  -> GraphStore 保存真实抽取结果
  -> knowledge-service 保留自由关系并做视图聚合
  -> 前端“泛化关系/弱关联”开关只过滤当前画布
```

关闭泛化关系时：

```text
原始图谱边
  -> 移除 RELATED_TO / 相关 / 关联 / 同现 等弱关系
  -> 根据剩余边重新计算可见节点
  -> 没有任何可见边连接的节点不再留在画布上
```

## 5. Key Code Concepts

**关系保真**

关系保真指的是：LLM 或规则抽取出来的 `relation` 原样传到视图层，不因为不是固定枚举就变成 `RELATED_TO`。这次 `knowledge-service` 只把明确的弱关联标签归一为泛化关系，像“面向”“生成”“约束”“使用”这类自由关系会保留。

**泛化关系只做显示过滤**

泛化关系不再是入库阶段的用户选择，而是前端画布的显示开关。这样同一份图谱数据可以同时支持“看完整结构”和“只看具体关系”。

**展示层不能造事实**

画布为了好看自动补 `RELATED_TO` 会污染事实边。现在 `ensureDisplayEntityRelations` 不再生成边，图谱事实只来自抽取和存储。

## 6. Important Implementation Details

- 旧接口字段 `graph_relation_mode` 没有删除，避免旧客户端请求失败；但后端会统一归一到 `balanced`。
- 前端关闭泛化关系后不会再因为“非泛化边为空”回退显示原始泛化边。
- 关系去重 key 包含 `source/target/relation/document_id/evidence`，避免不同证据支持的同类关系被吞掉。
- G6 边标签始终写入模型；边很多时缩短标签长度，详情面板仍显示完整关系和证据。
- 旧图谱数据不会自动变好，需要用户用“重建当前图谱”或“重建全部图谱”重新抽取。
