# Change Note: 知识图谱邻域与路径查询

## 1. What Changed

本次继续完善 knowledge-service 的知识图谱能力，新增两个核心查询：

- 节点邻域子图：围绕某个实体展开一跳或多跳邻居。
- 两节点最短路径：在当前用户可见图谱中查找两个实体之间的最短关系链，并返回可高亮的 node_ids 和 edge_ids。

前端知识图谱页面也增加了对应交互：点击节点后可以查看邻域、设为路径起点、设为路径终点，路径查询成功后会在 G6 图谱中高亮对应节点和关系。

这是一次功能新增、RPC 契约扩展、前端交互增强和文档更新。

## 2. Why This Change Was Needed

只展示完整图谱还不够。用户真正学习项目结构时，经常会问两类问题：

- “这个节点周围有什么？”例如查看 `agent-manager-service` 关联了哪些表、Topic 和服务。
- “这两个东西怎么连起来？”例如查看 `agent_dispatch_records` 到 `agent-runtime-service` 的关系路径。

如果只能看全图，节点多时很容易乱。邻域查询和路径查询让 knowledge-service 从“展示图”变成“可探索图”，也为后续 GraphRAG 在线查询中的 entity linking、subgraph retrieval 和 path reasoning 打基础。

## 4. Core Flow After The Change

邻域查询：

```text
点击节点「查看邻域」
  -> GET /api/v1/knowledge/node/:id/neighborhood
  -> api-gateway KnowledgeHandler
  -> knowledge-service RPC
  -> knowledgeclient 从 GraphRAG 子图中按 hops 展开节点
  -> 返回子图 nodes / edges / communities / stats
  -> 前端重新渲染图谱
```

路径查询：

```text
用户设置起点和终点
  -> GET /api/v1/knowledge/path?source_id=&target_id=
  -> knowledge-service 读取当前可见图谱
  -> 使用 BFS 查找最短路径
  -> 返回 path nodes、path edges、node_ids、edge_ids
  -> 前端按 node_ids / edge_ids 设置 selected 状态
```

## 5. Key Code Concepts

**邻域子图**

从一个中心节点开始，沿关系边展开 1 到 3 跳，返回只包含相关节点和边的子图。这样用户可以聚焦一个服务、表或 Topic，而不是被全图淹没。

**最短路径**

当前实现把图谱关系视为无向边，用 BFS 找最短链路。这适合可视化探索，因为用户关心“是否有关联”和“中间经过什么”。后续如果要做严格方向推理，可以增加 directed path 模式。

**路径高亮**

后端返回 `node_ids` 和 `edge_ids`，前端不需要重新推导路径，只要把对应 G6 item 设置为 selected。这让展示逻辑简单且稳定。

**权限边界**

路径和邻域都只基于 rag-service 返回的 viewer 可见子图计算，不会绕过底层权限裁剪。

**过滤一致性**

邻域查询和路径查询会复用前端当前的实体类型、关系类型和社区过滤条件，避免用户已经过滤后的画布在二次探索时又混入被过滤掉的节点或关系。

- 后续可把路径查询结果作为 GraphRAG 回答的结构化证据之一。
